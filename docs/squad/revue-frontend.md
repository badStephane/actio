Date : 2026-11-07. Rôle : Développeur Front-End (mode Revue, lecture seule).

## Hypothèses
- H-F1 : app desktop Tauri (fenêtre min 900 px de large). Entre 900 et 1023 px la sidebar passe en mode tiroir (`lg:`), c'est voulu.
- H-F2 : WebView2 (Windows) et WKWebView (macOS) ; F5 n'est pas un geste connu des opérateurs, un écran blanc équivaut à un plantage.
- H-F3 : les montants sont des entiers en F CFA ; la gratuité (montant 0) est une question produit, posée en fin de document.
- tsc et lint ont été lancés sur une copie du dépôt (`npm ci --ignore-scripts` dans un dossier temporaire), le dépôt n'a pas été modifié.

## Conformités vérifiées (pas d'action)
- Vérification de mise à jour hors ligne silencieuse et non bloquante (`UpdateChecker.tsx:25-28`).
- Liste paginée (10 à 100 lignes, `RegistrationList.tsx:297-301`) : pas besoin de virtualisation pour quelques milliers d'inscriptions.
- `ConfirmModal` : `role="dialog"`, `aria-modal`, Échap, piège de focus, focus initial sur Annuler. `Toast` : `role="status"`.
- Confirmation avant suppression d'inscription, d'activité, restauration, effacement du journal, réinitialisation.
- Déverrouillage : bouton « Vérification... » désactivé pendant le PBKDF2 (`AuthGate.tsx:304-313`). Verrouillage auto configurable (désactivé par défaut).
- `prefers-reduced-motion` respecté (`index.css:97-104`), anneau `:focus-visible` présent (`index.css:16-18`).

## Corrections proposées (Bloquant et Majeurs)

**B1 : restauration sûre.** Dans `dbBackup.ts` : (1) avant `db.close()`, lire les 16 premiers octets du fichier choisi (`readFile` de `@tauri-apps/plugin-fs` ; le chemin choisi via le dialogue entre dans le scope) et refuser si ce n'est pas `"SQLite format 3\0"` ; (2) copier la base courante vers `AppData/backups/inscriptions-avant-restauration-<horodatage>.db` (`copyFile` avec `BaseDirectory.AppData`, `mkdir` récursif) ; (3) exporter `resetDb()` dans `db.ts` (`dbPromise = null`) et l'appeler dans un `finally` après `close()` ; (4) dans `confirmRestore`, en cas d'erreur après fermeture, faire `window.location.reload()` au lieu du seul toast. Message de confirmation : « Les inscriptions, activités, l'historique et le mot de passe seront remplacés par ceux du fichier. Une copie de la base actuelle sera conservée. » Le chemin de retour arrière est assuré par l'écran d'erreur de M8.

**M1 : erreur d'enregistrement visible.** Ajouter `const [submitError, setSubmitError] = useState<string | null>(null)` ; dans le `catch` de `persist`, `setSubmitError("L'inscription n'a pas pu être enregistrée. Vos informations sont conservées, réessayez.")` ; le remettre à `null` au début de `handleSubmit`. Afficher `<div role="alert" className="... bg-red-50 ...">` juste avant la barre d'actions (même style que `ActivityFormModal.tsx:215-220`).

**M2 : anti double soumission.** `const submittingRef = useRef(false)`. En tête de `handleSubmit` (après `preventDefault`) : `if (submittingRef.current) return; if (!validate()) return; submittingRef.current = true; setIsSubmitting(true);`. Garder le verrou pendant l'affichage de la modale de doublon. Le libérer (`submittingRef.current = false; setIsSubmitting(false)`) en cas d'erreur, d'annulation de la modale (`onCancel`) ou d'échec de `persist`, mais pas en cas de succès (la redirection suit). `persist` ne touche plus à `isSubmitting` au début.

**M3 : vrais états d'erreur.** Pour chaque écran, `const [loadError, setLoadError] = useState(false)` mis à `true` dans le `catch`, et une fonction `load` réutilisable. Rendu : un composant partagé `LoadError({ message, onRetry })` (`AlertCircle`, texte « Impossible de charger les données. », bouton « Réessayer »), placé avant le test d'état vide. Home : ne plus faire `setData({ registrations: [], activities: [] })`. Liste : masquer Restaurer et Excel tant que `loadError`. Activités : `const [countsLoaded, setCountsLoaded] = useState(false)` et afficher Supprimer seulement si `countsLoaded && counts[a.id] === 0`. Stats : distinguer `notFound` (activité absente) de `loadError`. Formulaire : si les activités ne chargent pas, message sous le `select` et bouton Enregistrer désactivé.

**M4 : ErrorBoundary.** Nouveau `src/components/ErrorBoundary.tsx` (composant de classe, `getDerivedStateFromError`, `componentDidCatch` avec `console.error`). Fallback : « Une erreur inattendue est survenue. Vos données enregistrées ne sont pas affectées. » + boutons « Retour à l'accueil » (`window.location.assign('/')`) et « Recharger » (`window.location.reload()`). L'utiliser dans `main.tsx` autour de `<App />` et dans `App.tsx` autour de `<Routes>` avec `key={location.pathname}` (via un petit composant qui lit `useLocation`) pour se réinitialiser à la navigation.

**M5 : verrouiller sans perdre la saisie.** Dans `ProtectedGate`, mémoriser `hasUnlockedOnce`. Quand `phase === 'lock'` et `hasUnlockedOnce`, rendre `<><div inert aria-hidden="true">{children dans le Provider}</div><LockScreen className="fixed inset-0 z-[60]" /></>` au lieu de remplacer l'arbre. L'écran de verrouillage est opaque (dégradé actuel), le contenu reste monté donc la saisie est conservée. Garder le comportement actuel (rien de monté) avant le premier déverrouillage. Vérifier que les raccourcis clavier des modales sont neutralisés par `inert`.

**M6 : préserver le code de récupération.** (Rôle Back/Sécurité, fichier `auth.ts`.) Remplacer `DELETE` + `INSERT` par `INSERT INTO auth_settings (id, password_hash, salt, iterations, created_at) VALUES (1, $1, $2, $3, $4) ON CONFLICT(id) DO UPDATE SET password_hash = excluded.password_hash, salt = excluded.salt, iterations = excluded.iterations`. Si le PM veut un code à usage unique après récupération, l'effacer explicitement dans `RecoveryUnlockModal` et l'afficher : « Votre code de récupération a été utilisé, définissez-en un nouveau. »

**M7 : réinitialisation protégée.** Avant `resetAuthAndData()`, copier la base vers `AppData/backups/inscriptions-avant-reinitialisation-<horodatage>.db`, comme pour B1. Ajouter à `ConfirmModal` une prop optionnelle `confirmText?: string` : un champ « Tapez EFFACER pour confirmer » et Confirmer désactivé tant que la saisie ne correspond pas. Texte : « Une copie de sécurité sera conservée dans le dossier de l'application. »

**M8 : erreur de base au démarrage.** Ajouter `'error'` à `Phase`. Dans le `catch` de `hasPassword` : `setPhase('error')`. Écran : « Impossible d'ouvrir la base de données » + « Réessayer » (`resetDb()` puis relancer la vérification) + « Restaurer la dernière copie de sécurité » si un fichier existe dans `AppData/backups` (lien avec B1/M7). Ne jamais passer en `setup` sur une erreur.

**M9 : stats du bon périmètre.** Introduire `const scopedRegistrations = useMemo(() => filterActivity ? registrations.filter(r => r.activityId === filterActivity) : registrations, [registrations, filterActivity])` et calculer `stats` dessus (la recherche et les dates restent hors des totaux). Libellé « Montant total » suivi du nom de l'activité. La carte « Toutes les inscriptions » de l'écran de sélection garde les totaux globaux.

**M10 : montant entier.** Validation : `const raw = formData.amount.replace(/\s/g, ''); if (!/^\d+$/.test(raw)) newErrors.amount = 'Montant entier en F CFA, sans décimales';` puis `Number(raw) < MIN_AMOUNT`, avec `MIN_AMOUNT = 0` ou `1` selon la décision PM. Champ : `step="1"`, `inputMode="numeric"`. `buildPayload` : `amount: parseInt(raw, 10)`. Même règle dans `ActivityFormModal.tsx:73-81` et dans `importRegistrations.ts:136` (rôle Back pour l'import).
